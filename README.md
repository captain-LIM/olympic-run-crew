# 🎤🏃 공연 전 한 바퀴

**같은 공연을 보러 온 사람들끼리, 공연 전 1시간 올림픽공원을 함께 걷고 달리는 번개 매칭 서비스**

> 한국체육산업개발(주) 개방 공공데이터 활용 공모전 출품작
> 활용 데이터: 올림픽공원 대관정보 · 주차장 혼잡도 정보 · 올림픽공원 공연장 실감형 콘텐츠
> 연계 데이터: KOPIS 공연 일정 (출처 : (재)예술경영지원센터 공연예술통합전산망, www.kopis.or.kr)

## 기획 배경

KSPO DOME, 올림픽홀 같은 올림픽공원 공연장의 관객은 공연 시작 몇 시간 전에 도착하는 경우가 많습니다. 굿즈를 사고, 주차 혼잡을 피하고, 입장 대기를 하다 보면 **공연 전에 1~3시간이 그냥 지나갑니다.** 이 시간은 대부분 근처 카페나 공연장 앞에서 혼자 보내게 됩니다.

반면 바로 옆에는 산책로와 러닝 코스가 좋은 올림픽공원이 있습니다.

**"공연 전 대기시간"이라는 숨은 수요**를 **"같은 공연을 좋아하는 사람과 공원을 한 바퀴 도는 경험"**으로 바꾸는 것이 이 서비스의 목표입니다.

- **관람객:** 혼자 기다리던 시간이 같은 취향을 가진 사람과의 가벼운 만남이 됩니다.
- **공원 운영:** 관객을 특정 주차장과 공연장 앞에서 공원 곳곳으로 **분산**시킵니다.
- **공연장:** 실감형 콘텐츠로 공연장을 미리 경험하게 해 기대감과 재방문을 높입니다.

## 핵심 기능

| 기능 | 설명 |
|---|---|
| 🎫 **공연별 매칭 룸** | 공연을 검색해 고르고 날짜·시각을 정하면 **같은 공연·같은 날짜** 관객끼리 매칭 풀이 만들어집니다. 앞으로 90일 안의 올림픽공원 공연은 KOPIS 일정으로 **회차를 골라** 정하고(홈의 '곧 열리는 공연'), 대관정보 API의 공연(700여 건)은 티켓의 날짜·시각을 입력합니다. |
| ⚡ **번개 매칭** | 같은 공연, 같은 날짜, 같은 모드(산책/조깅/러닝), 출발 시각 ±15분, 페이스 ±1분/km 조건으로 크루를 찾습니다. 맞는 크루가 없으면 새 번개를 엽니다. |
| ⏱️ **입장 시간 역산** | `공연 시작 − 입장 여유 30분 − 코스 소요 − 공연장까지 이동`을 계산해 공연에 늦지 않는 출발 시각만 허용합니다. |
| 📈 **공연일 혼잡 예측** | 주차 혼잡 이력과 공연장 규모를 합쳐 **"이 공연은 몇 시부터 관객이 몰리고, 몇 시에 가장 붐비는지"**를 30분 단위로 예측하고, 가장 한산한 **추천 산책 시간**을 알려줍니다. |
| 🅿️ **혼잡 기반 분산 추천** | 출발 시각의 예측 혼잡도가 높으면 공연장 바로 앞이 아닌 공원 안쪽 집결지로 분산시킵니다. |
| 👤 **회원가입·로그인** | 이메일·비밀번호 계정(scrypt 해시, httpOnly 세션 쿠키). 크루·채팅·보상이 계정에 저장됩니다. |
| 💬 **크루 채팅** | 크루 멤버끼리만 보이는 채팅. 도배 방지(1초 1건·1분 30건)와 500자 제한이 있고, 공연 3시간 후 종료됩니다. |
| 🚨 **신고·차단** | 크루원·메시지 신고(사유 선택), 서로 다른 2명 이상이 신고한 메시지는 자동으로 가려집니다. 차단하면 서로의 채팅이 보이지 않고 같은 번개에 매칭·참여되지 않습니다. |
| 📍 **위치 체크인** | 출발 30분 전부터 집결지 반경 300m 안에서 GPS로 체크인합니다. 수동 체크인도 지원합니다. 체크인 가능 시간(출발 30분 전~공연 3시간 후)과 '체크인 후 완주' 순서는 서버가 검증합니다. |
| 🔎 **열린 번개 한눈에** | 홈에서 내가 참여 중인 번개와 모집 중인 번개를, 공연 페이지에서 그 공연의 열린 번개를 로그인 없이 볼 수 있습니다(10대·성인 분리, 차단 관계 반영, 닉네임 비공개). |
| 🔗 **공유·알림** | 크루방 링크를 공유하거나 복사하고, 탭이 열려 있는 동안 새 채팅 메시지를 브라우저 알림으로 받을 수 있습니다. |
| 📅 **캘린더·길찾기** | 크루 멤버는 출발 일정을 휴대폰 캘린더(.ics)나 Google 캘린더에 넣어 **출발 30분 전 알림**을 받을 수 있습니다. 집결지는 **카카오맵 길찾기**로 바로 엽니다. 일정에는 크루원 닉네임을 넣지 않습니다. |
| 🏟️ **실감형 3D 공연장** | 공연장 3D 모델을 웹에서 회전하고 확대해 볼 수 있습니다. 작은 화면·데이터 절약·느린 회선에서는 큰 모델(KSPO DOME 약 27MB 등)을 용량 안내 후 "3D 불러오기"를 눌러야 받습니다. |
| 🎁 **완주 보상** | 크루 코스를 완주하면 해당 공연장의 **'무대 앞 시점'**이 해금됩니다. 완주 카드와 내 계정의 "무대 시점 보기" 버튼으로 바로 다시 볼 수 있습니다. |
| 🖼️ **완주 기록 카드** | 완주하면 공연 제목·거리·코스·크루 인원이 담긴 이미지 카드를 저장하거나 공유할 수 있습니다. 닉네임과 연락처는 넣지 않습니다. |
| 🏅 **배지·누적 기록** | 내 계정에서 완주 횟수, 누적 km, 완주한 공연장 수와 배지 5종(첫 한 바퀴·단골 러너·공연 전 루틴·10km 클럽·공연장 투어), 공연장 완주 지도를 볼 수 있습니다. |
| 🛡️ **안전 설계** | 만 14세 미만은 이용할 수 없고, 10대는 10대 전용 크루로 분리합니다. 실명과 연락처는 받지 않고, 집결지는 공개 장소만 씁니다. |

### 데이터 처리 방식

- **대관정보:** 응답에 행사 날짜 필드(`temporalCoverage`)가 비어 있습니다. 그래서 공연 카탈로그로만 쓰고, **날짜·시각은 사용자가 티켓 기준으로 입력**합니다. 중복 공연은 제거하고 최근 공연부터 보여줍니다. API 호출은 하루 단위로 캐시합니다.
- **주차장 혼잡도:** 원본의 `등록시간` 분:초 자리에 월:일 값이 들어가 있어 **'시'만 사용**합니다. 혼잡 이력 지수는 `(요일유형·시간대 ±1h 기록의 가중치 합: 원활 0 / 혼잡 0.6 / 만차 1) ÷ 관측일 수`를 0~1로 정규화한 값입니다. 원본(EUC-KR)은 UTF-8로 변환해 저장했습니다.
- **실감형 콘텐츠:** 원본 GLB를 [glTF-Transform](https://gltf-transform.dev) meshopt로 압축해 `public/models/`에 넣었습니다. KSPO DOME은 SketchUp DAE 원본(453MB, 메시 10만 개·삼각형 263만 개)만 제공되어, 직접 만든 스트리밍 변환기(`scripts/sketchup-dae-to-glb.mjs`)로 GLB로 변환한 뒤 압축했습니다(453MB → 26MB). 5개 공연장 모두 웹에서 3D로 볼 수 있고, 실내 공연장은 **지붕을 잘라 내부를 보는 단면 보기**를 지원합니다.
- **KOPIS 공연 일정:** 공연 목록(가이드상 조회 기간 최대 31일·한 번에 100건)을 31일씩 3번 나눠 앞으로 90일을 받고, 공연마다 상세를 받습니다. 상세의 공연 시각(`dtguidance`, 예: `수요일 ~ 금요일(19:30), 토요일(15:00,19:00)`)을 요일별 시각으로 해석해 공연 기간 안의 날짜로 펼칩니다. 이 값은 **요일별 안내**라 공휴일·특별 회차는 다를 수 있어서, 화면에 "티켓의 날짜·시각과 같은지 확인" 안내와 **직접 입력**을 함께 둡니다. 공휴일 회차(`HOL(…)`)는 어느 날이 공휴일인지 응답에 없어 목록에 넣지 않고 안내만 합니다. 모르는 형식이면 회차 목록 없이 직접 입력으로 바뀝니다. 공연장은 KOPIS 공연장 코드(`FC001247-01` = KSPO DOME 등)로 정합니다.
- **KOPIS 이용 조건:** KOPIS OPEN API 이용제한은 ① IP당 1초에 10회 이상 호출 시 서비스 중지, ② 출처 미기재 시 서비스 중단 가능(예: `출처 : (재)예술경영지원센터 공연예술통합전산망, www.kopis.or.kr`), ③ 인증키 1인 1개입니다. 상업적 이용은 가능합니다.
  - 호출: 요청 시작 간격을 0.2초(초당 최대 5회)로 두고, 결과를 6시간(공연 상세는 24시간) 캐시합니다. 캐시가 지나도 이전 결과를 바로 보여주고 뒤에서 새로 받으므로, 평소 호출은 6시간에 약 25회입니다. 동시에 4개씩 불렀을 때 실제로 `400 Request Blocked`가 오고 약 5분 뒤 풀리는 것을 확인했습니다.
  - 출처: 모든 화면 하단, 홈의 '곧 열리는 공연', 공연 화면에 위 예시 형식 그대로 표시합니다.
- **API 장애 대비:** 대관정보 API 호출이 실패하면 기본 공연 목록으로 대체되어 서비스는 계속 동작합니다. KOPIS 키가 없거나 호출이 실패하면 KOPIS 공연 없이 기존처럼 동작하고(실패 후 5분간 재호출 안 함), 이미 열린 KOPIS 공연 번개의 크루방은 공연 이름 대신 안내 문구로 열립니다.

### 혼잡 예측 모델 (`src/lib/prediction.ts`)

```
예측지수(t) = min(1, 기저(t) × 0.6 + 공연부하(t))
  기저     = 주차장 혼잡도 CSV로 만든 요일유형·시간대 혼잡 이력 지수 (분 단위 보간)
  공연부하 = 규모계수 × max(본 도착 분포, 조기 도착 분포 × 0.45)
             본 도착: 공연 70분 전 중심(σ 45분) / 조기 도착(굿즈·대기): 공연 3시간 전 중심(σ 60분)
  규모계수 = (공연장 수용 인원 / 15,000)^0.6   — KSPO DOME 만석 공연 = 1
```

- **관객 몰림 시작:** 공연부하가 0.3을 넘는 첫 시각
- **추천 산책 시간:** 출발 가능 구간(공연 150분 전 ~ 60분 전) 중 예측지수 평균이 가장 낮은 60분 구간
- 예) 토요일 18시 KSPO DOME 공연 → 14:30부터 관객 몰림, 17:00 전후 최고, 추천 산책 15:30~16:30
- 공연일과 주차 기록을 직접 연결한 데이터가 없어 도착 분포·규모계수는 가정값입니다. '올림픽공원 차량입출차·공연·날씨 연계 데이터(15164822)'로 보정할 수 있습니다.

## 서비스 흐름

```
홈 (3단계 안내 · 내가 참여 중인 번개 · 모집 중인 번개 · 공연 목록 + 혼잡도)
   └─▶ 공연 선택 → 열린 번개 목록 → 티켓 날짜·시각 입력 → 📈 공연일 혼잡 예측 · 추천 산책 시간
         ├─ (로그인/회원가입)
         ├─ 조건 입력 (활동 종류 · 페이스 · 출발 시각)
         ├─ 같은 공연 크루 찾기 ──▶ 참여
         └─ 새 번개 열기 (예측 혼잡 반영 코스 추천 · 입장 시간 검증 · 확인 창)
               └─▶ 크루룸
                     ├─ 출발/공연 카운트다운 · 링크 공유 · 집결지 지도
                     ├─ 💬 크루 채팅(알림) · 🚨 신고/차단
                     ├─ 위치 체크인(출발 30분 전부터) → 완주 → 🖼️ 기록 카드 · 🏅 배지
                     └─▶ 🎁 공연장 3D '무대 시점' 해금 (계정에 저장)
```

## 디자인

밝고 활기찬 스포츠·러닝 앱 느낌으로, 공연 전 올림픽공원을 달리는 마스코트가 서비스의 얼굴이 되도록 구성했습니다. 디자인 시스템은 [Hallmark](https://skills.sh/Nutlope/hallmark) 규칙(토큰 하나로 색·폰트 관리, 포커스 링, 대비, 모션 최소화 등)으로 점검했습니다.

### 디자인 원칙

- **흰 바탕 + 하늘색 + 로열블루:** 페이지는 흰색에 가까운 연한 블루그레이, 주 버튼과 선택 상태는 로열블루, 글자는 네이비입니다.
- **크게 둥근 카드:** 카드 모서리 28px, 버튼·칩·태그는 알약 모양, 부드러운 블루 그림자를 씁니다.
- **혼잡도는 신호등처럼:** 여유 하늘색, 보통 노랑, 혼잡 오렌지, 매우 혼잡 네이비로 막대 차트와 태그에 같은 색을 씁니다.
- **번호 원형 목록:** 공연 목록, 모집 중인 번개, 내 번개에 `01`, `02` 번호 원을 붙이고 마우스를 올리면 파랗게 채워집니다.
- **폰트 하나:** 한글에 강한 SUIT Variable 한 가지로 제목과 본문을 통일했습니다.
- **접근성:** 키보드 포커스 링, 입력칸 경계 대비 3:1 이상, 장식 이미지는 스크린리더에서 숨김, `prefers-reduced-motion` 대응, 본문 바로가기 링크.

### 모바일·노트북 대응

- **내비게이션:** `공연장 3D` · `내 번개`(내 계정의 참여 중인 번개) · 로그아웃. 터치 영역은 44px 이상입니다.
- **공연 페이지:** 모바일에서는 열린 번개, 티켓 정보, 혼잡 예측 요약, 조건 순으로 쌓고 시간대 그래프는 접어 둡니다. 노트북에서는 예측 카드가 오른쪽에 고정됩니다.
- **오류·진행 표시:** 찾기, 참여, 번개 열기 오류를 각 버튼 바로 아래에 보여주고, 검색 중에는 "찾는 중…"과 결과 위치로 스크롤합니다.
- **크루방:** 모바일에서는 상단의 "채팅 바로가기"로 채팅으로 이동하고, 체크인이 열리기 전에는 안내 한 줄만 보입니다.

### 마스코트

마스코트 시트 한 장(`1254×1254`, 흰 배경)을 포즈 7개의 투명 PNG로 잘라 `public/mascot/`에 두었습니다. 다시 만들려면 시트 경로를 넘겨 실행합니다.

```bash
node scripts/cut-mascot.mjs <마스코트-시트.png>
```

| 포즈 | 쓰는 곳 |
|---|---|
| `hero` 폰을 들고 올림픽공원을 달림 (배경 포함) | 홈 히어로 |
| `peek` 기둥 뒤에서 빼꼼 | 홈 혼잡도 섹션, 로그인 |
| `run` 달리기 | 홈 공연 찾기, 크루룸 헤더 |
| `cheer` 야광봉 응원 | 공연 상세 헤더, 회원가입, 완주 보상 |
| `phone` 폰 확인 | 로그인 안내, 채팅 빈 화면 |
| `concert` 공연장 뒷모습 | 3D 링크, 공연장 3D 페이지 |
| `rest` 잔디밭 휴식 | 내 계정 |

`Mascot` 컴포넌트(`src/components/Mascot.tsx`)로 불러 쓰며, 새 포즈를 추가하려면 `scripts/cut-mascot.mjs`의 크롭 좌표와 `Mascot.tsx`의 크기 표에 함께 넣으면 됩니다.

## 기술 스택

- **Framework:** Next.js 15 (App Router) · React 19 · TypeScript
- **Styling:** Tailwind CSS 4 · 공용 스타일 `src/app/ui.css` · 디자인 토큰 `src/app/tokens.css` (모바일 우선)
- **Font:** SUIT Variable (CDN)
- **DB:** MySQL 8 (mysql2) · 스키마 `db/schema.sql`
- **Auth:** scrypt 비밀번호 해시 · DB 세션(토큰 SHA-256 저장) · httpOnly 쿠키
- **3D:** Three.js (GLTFLoader + meshopt, OrbitControls)
- **Data:** fast-xml-parser (공공데이터 XML 파싱)
- **Test:** Vitest

## 시작하기

```bash
git clone https://github.com/captain-LIM/olympic-run-crew.git
cd olympic-run-crew

cp .env.example .env.local   # 값 채우기 (아래 참고)

```

브라우저에서 http://localhost:3000 에 접속합니다.

### MySQL 준비

MySQL 8에 데이터베이스와 앱 전용 계정을 만들고 `.env.local`에 접속 정보를 넣습니다.

```sql
CREATE DATABASE olympic_run_crew CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'orc_app'@'localhost' IDENTIFIED BY '<비밀번호>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES ON olympic_run_crew.* TO 'orc_app'@'localhost';
```

```bash
DATABASE_URL=mysql://orc_app:<비밀번호>@localhost:3306/olympic_run_crew
```

테이블: `users` · `sessions` · `crews` · `crew_members` · `messages` · `reports` · `blocks` · `user_rewards` · `rate_limits` (모든 시각은 UTC 저장)

> 새 테이블이 추가되면 각자 로컬 DB와 배포 DB에서 `npm run db:migrate`를 다시 실행하세요. 기존 테이블은 건드리지 않고, 여러 번 실행해도 안전합니다.

### 요청 횟수 제한

로그인·회원가입·채팅의 요청 횟수를 `rate_limits` 테이블에 기록해 제한합니다(`src/lib/rateLimit.ts`). 서버 메모리가 아니라 DB에 두므로 재시작하거나 Vercel처럼 서버 인스턴스가 여러 개여도 같은 기록을 봅니다. 이메일·IP는 SHA-256 해시로만 저장합니다.

| 대상 | 한도 |
|---|---|
| 로그인 실패 | IP당 20회/10분 · 같은 IP의 같은 이메일 5회/10분 · 이메일 전체 50회/시간 |
| 회원가입 | IP당 5회/시간 |
| 채팅 | 사용자당 1초 1건 · 1분 30건 |

IP는 `X-Forwarded-For`의 첫 값을 씁니다. **Vercel은 이 헤더를 실제 접속 IP로 덮어쓰므로 믿을 수 있습니다.** Vercel 앞에 다른 CDN(Cloudflare 등)을 두거나, 프록시 없이 `next start`를 바로 노출하면 이 값이 프록시 IP가 되거나 사용자가 조작할 수 있으니 `clientIp()`를 다시 봐야 합니다.

### 공공데이터 API 연결

1. [공공데이터포털](https://www.data.go.kr)에서 '한국체육산업개발(주)_올림픽공원대관정보'를 활용신청합니다.
2. `.env.example`을 `.env.local`로 복사하고 서비스키를 넣습니다. (`.env.local`은 git에 올라가지 않습니다)

```bash
KSPO_RENTAL_SERVICE_KEY=발급받은_서비스키
```

3. (선택) [KOPIS 공연예술통합전산망](https://www.kopis.or.kr/por/cs/openapi/openApiInfo.do)에서 OpenAPI 인증키를 받아 넣으면 예정 공연의 회차를 고를 수 있습니다. 없으면 이 기능만 빠지고 나머지는 그대로 동작합니다.

```bash
KOPIS_SERVICE_KEY=발급받은_인증키
```

Vercel에 배포할 때는 같은 이름의 환경변수를 프로젝트 설정(Settings → Environment Variables)에 넣습니다. 키는 서버에서만 쓰고 브라우저로 보내지 않습니다.

주차장 혼잡도와 실감형 콘텐츠는 파일 데이터라 저장소에 포함되어 있어 별도 설정이 필요 없습니다.

### 3D 모델 다시 만들기

원본은 [올림픽공원 공연장 안내 페이지](https://www.ksponco.or.kr/menu.es?mid=a10405050100)에서 받을 수 있습니다. 원본 GLB를 받은 뒤 아래 명령으로 압축합니다.

```bash
npx @gltf-transform/cli@4.1.1 optimize SKHandBall.glb public/models/handball.glb --compress meshopt --texture-compress false
```

KSPO DOME(DAE 원본)은 먼저 GLB로 변환한 뒤 같은 방식으로 압축합니다.

```bash
npm run convert:dae -- "<경로>/source/temp_export/temp_export.dae" "<경로>/source/temp_export/temp_export,<경로>/textures" kspo-dome-raw.glb
npx @gltf-transform/cli@4.1.1 optimize kspo-dome-raw.glb public/models/kspo-dome.glb --compress meshopt --texture-compress false
```

## 한계와 향후 계획

- **공연 일정:** 대관정보 API에 날짜가 없고 2022년 공연까지만 있어, KOPIS 공연 일정을 연계했습니다. KOPIS 공연 시각은 요일별 안내라 공휴일·특별 회차는 사용자가 직접 입력해야 합니다.- **좌표와 코스:** 코스·공연장 좌표는 근사값입니다. 주차구역(P1A~P11)의 위치 정보가 공개되면 구역 단위 분산 안내로 확장할 수 있습니다.
- **예측 보정:** 혼잡 예측의 도착 분포·규모계수는 가정값입니다. 입출차·공연 연계 데이터(15164822)로 보정할 계획입니다.
- **실시간 채팅:** 현재 3초 간격 폴링입니다. 사용자가 많아지면 WebSocket/SSE로 전환합니다.
- **신고 처리:** 신고는 DB에 쌓이고 메시지 자동 가림까지 동작합니다. 운영자 검토 화면은 추후 추가합니다.
- **공연장 내 시설 안내:** 화장실·매점·물품보관 위치는 공개 데이터로 확인되지 않아 넣지 않았습니다. 공연장 운영처의 공식 도면을 받으면 3D 위에 표시할 수 있습니다.
- **날씨 연계:** 기상청 단기예보와 연계해 비가 오거나 폭염인 날에는 실내 대기 모드로 전환합니다.
